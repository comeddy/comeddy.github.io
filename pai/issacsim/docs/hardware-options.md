# 장비별 경로

기본 교재와 코드는 **TurtleBot3 Burger + Raspberry Pi 4 + ROS 2 Humble** 한 조합을 목표로 합니다.
처음 배우는 사람에게 여러 하드웨어 분기를 한꺼번에 요구하지 않기 위한 선택입니다.

| 보유 장비 | 바로 가능한 범위 | 추가로 필요한 일 |
|---|---|---|
| 노트북만 | AWS 시뮬레이션·학습·평가 | 실물 주행에는 로봇 필요 |
| TurtleBot3 Burger/Pi4 | 기본 전 과정 | Ubuntu 22.04/Humble, LDS·펌웨어 확인 |
| Jetson Orin Nano/AGX Orin만 | 모델 파일 로딩·추론 | 360도 LDS, 구동 베이스, 모터 제어기와 ROS 드라이버 |
| Jetson + ROS 2 이동로봇 | 센서 입력 확인·그림자 실행부터 | 아래 인터페이스 일치와 별도 물리 검증 |
| 로봇팔/휴머노이드 | 개념·AWS 환경 일부 재사용 | 관측·행동·시뮬레이터·학습 과제 전체 재설계 |

## Jetson을 쓰려면

NumPy 모델은 CPU 추론도 가능하여 이 작은 정책에 TensorRT는 필수가 아닙니다.
Jetson의 JetPack, Ubuntu, ROS 배포판 호환성을 제조사 지원 표에 맞춰 선택하세요.
일반 Ubuntu 이미지를 Jetson에 임의로 덮어쓰는 방식은 안내하지 않습니다.

베이스의 ROS 인터페이스가 다음과 일치해야 합니다.

- `/scan`: `sensor_msgs/msg/LaserScan`, 360도, 미터, 로봇 전방 0rad, 반시계 양의 각도.
- `/cmd_vel`: Humble의 `geometry_msgs/msg/Twist`, m/s와 rad/s.
- `/odom`: `nav_msgs/msg/Odometry`, 주행 방향과 거리 확인용.
- 모터 컨트롤러: 새 명령이 끊어지면 짧은 시간 안에 정지하는 watchdog.

센서가 회전된 채 달려 있으면 TF가 있다는 사실만으로 정책 입력이 자동 보정되지 않습니다.
기본 노드는 임의의 센서 장착 변환을 수행하지 않으므로,
제조사 드라이버나 별도 변환 노드에서 실제 거리와 각도를 로봇 기준으로 맞춰야 합니다.
다른 바퀴 간격·차체 크기는 제동 거리와 정지 여유도 달라집니다.

**다른 로봇에 `/cmd_vel` 이름만 맞추어 바로 주행하지 않습니다.**
그림자 출력, 바퀴를 띄운 테스트, 시간 초과 정지, 낮은 속도의 순서로 검증합니다.
실제로 사용한 Jetson 모델·베이스·센서가 정해지면 그 조합에 맞춘 별도 교재가 필요합니다.

## 후속 2일차 예시

1. 카메라와 NVIDIA Replicator로 합성 이미지 생성.
2. 객체 탐지 모델 학습과 ONNX/TensorRT 배포.
3. 도메인 무작위화: 마찰, 센서 노이즈, 조명, 질량.
4. Isaac Lab에서 강화학습 환경 만들기.
5. Nav2와 결합한 목표 지점 이동.

위 항목은 아이디어이며 기본 과정에 구현된 기능으로 표시하지 않습니다.
