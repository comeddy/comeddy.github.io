# 운영자 리허설과 수업 진행

이 자료는 한 팀당 GPU EC2 1대, 실제 Burger 1대, 참가자 2–3명을 기준으로 설계했습니다.
개인 AWS 계정으로 먼저 리허설하세요. Workshop Studio의 관리형 계정에서
GPU 한도가 자동 제공되는 구성은 아닙니다.

## 전날 준비

| 시점 | 수행 |
|---|---|
| 최소 3–7일 전 | 참가 계정·리전·GPU 한도 16 vCPU 여유, 실제 AZ 용량 확인 |
| 전날 | Ubuntu AMI·R580 드라이버·Isaac Sim 5.1.0 이미지 실제 실행 |
| 전날 | 로봇 조립, 배터리 충전, Pi 이미지, LDS·OpenCR 드라이버 확인 |
| 전날 | 실습장 구성, 정상 전원 차단과 독립 정지 시험 |
| 시작 30분 전 | Wi-Fi/SSH, 계정 로그인, 모델·프리뷰 백업, 케이블 점검 |

승인 소요 시간과 GPU 용량은 보장할 수 없습니다.
인원이 많으면 팀별 리전·AZ·동시 기동 계획을 별도로 검토합니다.
운영자가 전날 실행해 둔 EC2는 밤새 비용이 발생하므로 준비 종료 후 중지하고,
당일 재시작 시 바뀐 공인 IP를 반영합니다.

| 시간 | 진행 | 강사의 핵심 설명 |

| 03:35–04:10 | 가상 검증 | 멈추기만 하는 모델도 실패 |

휴식과 식사 시간을 더하면 실제 행사는 더 길어집니다.
초기 OS 설치까지 수업에서 진행하려면 2일로 나누세요.
빠른 3시간 데모는 환경·실측 데이터·모델을 미리 준비하되
참가자가 직접 학습하지 않은 부분을 명확히 알려줍니다.

## 필수 리허설: 확인한 뒤 날짜를 기록

### AWS와 시뮬레이터

1. README의 로컬 테스트와 `scripts/cloud/verify-local.py`를 실행한다.
2. 직접 `deploy.sh --check`와 실제 스택 생성을 수행한다.
3. cloud-init, 호스트 재부팅, `bootstrap-host.sh verify`를 확인한다.
4. 컨테이너 Compatibility Checker의 `System checking result: PASSED`를 확인한다.
5. 1에피소드 smoke 실행에서 자산이 실제로 로드되고 PNG가 생성되는지 확인한다.
6. LDS 원점 높이·전방 방향·알려진 장애물 거리와 바퀴 회전 부호를 확인한다.
7. 30에피소드 데이터를 직접 수집하고 NumPy 학습을 실행한다.
8. 보지 않은 seed의 평가에서 모듈 6의 수치 기준과 근접·정체 검토를 모두 통과했는지 기록한다.
9. S3 업로드와 노트북 다운로드, 파일 해시 일치를 확인한다.
10. 파일을 보관한 뒤 실제 정리 스크립트로 스택과 과금 리소스가 삭제되는지 확인한다.

### 실제 로봇

1. 센서 모델·Pi OS·ROS·OpenCR 펌웨어와 소스 커밋을 기록하고 제공한 bringup 명령 만료 패치를 빌드한다.
2. 실제 `/cmd_vel`이 Twist이며 다른 publisher가 없는지 확인한다.
3. ROS_LOCALHOST_ONLY를 bringup과 정책 양쪽에 적용한다.
4. 실제 센서의 전방/좌우·누락값·주기·frame_id를 확인한다.
5. 그림자 모드가 모터 토픽에 발행하지 않는지 확인한다.
6. 바퀴를 띄워 장애물·센서 지연·노드 예외의 정지 고정을 확인한다.
7. 정책을 SIGKILL해 bringup은 살아 있어도 명령 만료 → heartbeat 중단으로 1.5초 이내 정지하는지 측정한다.
8. 드라이버 통신이 끊긴 경우에도 모터 컨트롤러가 정지하는지 확인한다.
9. 모듈 6의 수치 기준·근접·정체 검토와 위 실물 정지 검사를 모두 통과한 모델만 0.05m/s, 30초의 바닥 주행을 검증한다. 이번 리허설의 NO-GO 모델은 제외한다.
10. 종료 후 로봇과 서버의 잔여 프로세스·전원 상태를 확인한다.

**7번과 8번은 다른 시험입니다.** heartbeat가 유지된 채 명령 갱신만 끊기는 상황을
통신 단절 시험 하나로 대신하지 않습니다. 제공한 bringup 패치는 마지막 명령이
0.5초 이상 오래되면 heartbeat를 중단하지만, 펌웨어와의 합산 지연은 실물에서 확인해야 합니다.
패치가 적용되지 않았거나 정지가 늦으면 그림자 실습까지만 진행하고 구동을 보류합니다.

## 수업 중 자주 설명할 것

- “AI가 판단했다”와 “정지 검사에서 차단했다”를 구분합니다.
- AWS x86_64와 Pi arm64가 달라도 NumPy 가중치 파일은 공통 규약으로 읽습니다.
- 시뮬레이터 자산이 같아도 실제 마찰·센서·지연까지 자동 보정되는 것은 아닙니다.
- 실물 성공을 미리 약속하지 않고 학습·검증·개선을 한 바퀴 돌아보는 것이 목표입니다.
- 준비된 백업 모델을 사용한 팀은 직접 학습한 모델과 결과를 구분해 기록합니다.
