# 8. 바퀴를 띄워 확인하고, 바닥에서 30초

**시간: 65분 · 실행 위치: 로봇**

앞 모듈의 그림자 실행이 정상일 때 받침대 위 정지 검사를 진행합니다.
**바닥 주행은 모듈 6의 수치 기준과 근접·정체 검토를 모두 통과한 모델만 허용합니다.**
2026-09-09 리허설의 제공 모델은 NO-GO이므로 바닥 주행에 사용하지 않습니다.
이 코드는 교육용 장애물 회피 예제입니다. 계단·낙하 가장자리·사람이 다니는 공간에서 사용하지 않습니다.
한 사람은 터미널을 보고, 다른 사람은 로봇과 전원 스위치를 담당하면 진행하기 좋습니다.

:image[그림 6. 그림자 실행, 바퀴를 띄운 확인, 독립 정지 시험을 통과한 뒤 30초 저속 주행]{src="/static/images/concepts/deployment-stages.png" width=1200}

왼쪽 단계의 완료 확인을 통과한 뒤 오른쪽으로 이동합니다.
명령이 끊겼을 때의 정지는 바퀴를 띄운 상태에서 직접 측정해야 합니다.

## 8-1. 정지 방법부터

| 상황 | 정지 방법 |
|---|---|
| 정상 실행 중 종료 | 정책 터미널 `Ctrl+C` |
| 센서 지연·잘못된 입력 | 정책의 독립 타이머가 속도 0 발행, 오류 정지 고정 |
| 가까운 전방 장애물 | 0.35m 이하일 때 속도 0, 원인 제거 후 노드 재시작 |
| Python 프로세스 중단 | 패치된 bringup이 명령 만료 후 heartbeat 중단 → OpenCR 통신 timeout |
| bringup/ROS 통신 중단 | OpenCR 통신 timeout과 실제 모터 정지 확인 |
| 예상과 다르게 움직임 | 준비한 물리 전원 차단 사용 |

OpenCR의 **PUSH SW1/SW2는 주행 테스트 버튼**입니다. 비상 정지로 누르지 마세요.
전원 차단 위치와 배선은 자신의 조립 상태에서 확인해야 합니다.

Python의 센서 timeout은 **0.5초**, 검사 주기는 **0.05초**입니다.
OS 스케줄링 때문에 실제 정지 지연이 딱 0.55초로 보장되는 것은 아닙니다.
모델 프로세스 자체가 멈추면 Python 타이머도 실행되지 않으므로 아래 독립 정지를 확인합니다.
bringup 패치의 명령 만료 0.5초와 OpenCR heartbeat timeout은 연속해서 작동하므로
정지 시간에 둘 다 포함됩니다. 패치 없는 기본 bringup으로 이 단계를 진행하지 않습니다.

## 8-2. 바퀴를 띄운 상태에서 실행

그림자 실행을 `Ctrl+C`로 종료합니다. bringup은 유지합니다.
모든 터미널에 모듈 7의 ROS 환경을 적용한 상태에서 명령 publisher를 확인합니다.

```bash
ros2 topic info /cmd_vel --verbose
```

정책을 켜기 전 publisher가 0이어야 합니다. 두 개의 AI 노드, teleop, Nav2가
동시에 속도를 보내지 않도록 합니다.

```bash
cd ~/physical-ai-isaac-aws
python3 static/code/device/ros_policy_node.py \
  --model artifacts/policy.npz --arm --max-linear 0.05
```

`ARMED` 로그가 보여야 합니다. 첫 실제 전진 속도는 최대 초당 5cm입니다.
센서에 상자를 앞쪽 1m, 0.5m, 0.3m에 순서대로 놓아 속도 변화와 정지를 확인합니다.
0.3m에서 정지한 후 상자를 제거해도 자동 재개하지 않아야 합니다.
원인을 해결하고 노드를 종료·재시작해야 다시 움직일 수 있습니다.

## 8-3. 정책이 갑자기 죽었을 때

**계속 바퀴를 띄워 둡니다.** 전원을 차단할 준비를 합니다.
센서 앞을 비워 바퀴가 천천히 회전하게 하고, 다른 로봇 터미널에서 프로세스를 찾습니다.

```bash
pgrep -af ros_policy_node.py
```

출력에서 방금 실행한 정책의 PID 숫자 하나만 골라 넣습니다.

```bash
export POLICY_PID="<확인한 정책 PID>"
kill -KILL "$POLICY_PID"
```

강제 종료는 정책의 종료 콜백과 마지막 0 명령을 실행하지 않습니다.
그래도 **bringup이 살아 있는 상태에서 바퀴가 1.5초 이내 정지**하는지 측정합니다.
이 수치는 운영자가 확인해야 할 교육용 통과 조건이며 펌웨어의 보장값이 아닙니다.
멈추지 않으면 즉시 전원을 차단하고 bringup 패치·재빌드·재시작 여부와
OpenCR 펌웨어를 확인합니다. 보드의 debug mode·RC100 등 다른 제어 입력도 비활성화합니다.
**이 테스트가 실패하면 바닥 주행을 진행하지 않습니다.**

다음에는 안정적인 받침 상태에서 bringup 종료/통신 단절 때도 정지하는지 확인합니다.
정책만 죽는 경우와 모터 드라이버 통신이 끊기는 경우는 서로 다른 실패이므로 둘 다 기록합니다.

## 8-4. 바닥 주행

**시작 조건:** [모듈 6](../module6-evaluation/index.ko.md)의 이동·충돌·개입 수치 기준,
근접·정체 검토, 이 장의 모든 실물 정지 검사를 함께 통과해야 합니다. 하나라도 미통과이면
바닥에 내려놓고 실행하지 않습니다. 이번 리허설의 NO-GO 모델은 이 단계의 대상이 아닙니다.

승인된 모델인지 해시와 평가 기록을 확인한 뒤 AI 노드를 종료한 상태에서 로봇을 바닥에 둡니다.
2m × 2m 이상 공간의 바깥쪽에 큰 상자를 놓고 주변 사람을 물립니다.
첫 출발 지점의 전방을 1m 이상 비웁니다.

bringup과 센서 상태를 다시 확인한 뒤 30초 실행합니다.

```bash
cd ~/physical-ai-isaac-aws
timeout --signal=INT 30s python3 static/code/device/ros_policy_node.py \
  --model artifacts/policy.npz --arm --max-linear 0.05
```

30초 만료에 따른 `timeout` 종료 코드 124는 도구의 정상적인 시간 제한 표시입니다.
로봇이 실제로 멈추었는지 눈으로 확인합니다.
초기 실습은 `0.05m/s`를 유지하고, 속도를 올리는 것을 목표로 하지 않습니다.

다음 실행은 상자 위치를 바꿔 반복합니다.
로봇을 손으로 옮길 때는 항상 정책을 종료하고 바퀴가 멈췄는지 확인합니다.
정지 고정이 반복되면 실물 데이터를 분석하고 모듈 4–6으로 돌아갑니다.

## 8-5. 결과 기록

| 시도 | 배치 | 이동 여부 | 접촉 횟수 | 정지/개입 이유 | 비고 |
|---|---|---|---|---|---|
| 1 | 정면 상자 | 직접 기록 | 직접 기록 | 직접 기록 | 30초 |
| 2 | 왼쪽 상자 | 직접 기록 | 직접 기록 | 직접 기록 | 30초 |
| 3 | 오른쪽 상자 | 직접 기록 | 직접 기록 | 직접 기록 | 30초 |

진행자는 실제 환경의 증거와 영상을 남깁니다.
정상 종료 후 정책과 bringup을 `Ctrl+C`로 종료하고, 제조사 지침에 따라 OS와 전원을 끕니다.

**완료 확인:** 실제 센서 → 로컬 모델 → 속도 명령 → 바퀴 동작과 독립 정지를 확인했습니다.

**기억할 점:** 저속과 정지 검증은 실제 로봇에서 관찰한 결과로 판단합니다.
