# 4. 로봇의 연습장을 만들기

**시간: 45분 · 실행 위치: AWS EC2**

아직 AI가 운전하지 않습니다. 간단한 교사 규칙이 로봇을 움직이고
“그때 본 거리”와 “그때 선택한 속도”를 저장합니다.

## 4-1. 충분히 다양한 예시 수집

```bash
cd ~/physical-ai-isaac-aws
ACCEPT_EULA=Y bash scripts/cloud/run-headless.sh \
  static/code/sim/run_sim.py \
  --mode collect --episodes 30 --steps 600 --seed 42 \
  --output /output/dataset.npz
```

`episodes=30`은 서로 다른 출발·장애물 배치를 가진 30번의 실험입니다.
`steps=600`은 각 에피소드의 최대 제어 횟수입니다.
충돌 등으로 중단될 수 있어 저장된 행 수가 항상 18,000개인 것은 아닙니다.
`seed`는 난수의 시작값이며 같은 조건을 다시 실행하는 데 사용합니다.

학습 데이터는 실제 Isaac Sim 센서 계산에서 나옵니다.
로컬 단위 테스트에 쓰는 합성 입력은 이 워크샵의 실제 학습 데이터가 아닙니다.

## 4-2. 파일 안에는 무엇이 있을까?

:image[그림 4. 360도 거리 측정을 30도씩 12구역으로 묶고 구역별 가장 가까운 거리를 선택]{src="/static/images/concepts/lidar-sectors.png" width=1200}

센서 숫자 수백 개를 그대로 외우는 대신, 로봇 주변을 피자처럼 12조각으로 나눠 생각하세요.
각 조각에서 가장 가까운 물체까지의 거리 하나만 남깁니다.
전방의 양옆은 0번과 11번 구역이므로 두 구역을 함께 확인합니다.

| 배열 | 크기 | 의미 |
|---|---|---|
| `observations` | N × 12 | 12구역의 장애물 거리(m) |
| `actions` | N × 2 | 교사의 전진 속도와 회전 속도 |
| `episodes` | N | 몇 번째 실험에서 나온 행인지 |

12구역 입력은 모든 단계에서 같은 함수로 처리합니다.
전방은 0라디안, 왼쪽 방향이 양의 회전입니다.
전방을 가로지르는 구역은 첫 번째와 마지막 구역입니다.
거리 단위를 cm로 바꾸거나 구역 순서를 바꾸면 같은 모델로 사용할 수 없습니다.

## 4-3. 데이터를 확인

Isaac Sim 컨테이너에는 NumPy가 있으므로 다음 작은 검사 스크립트를 실행합니다.

```bash
ACCEPT_EULA=Y bash scripts/cloud/run-headless.sh \
  static/code/inspect_dataset.py --data /output/dataset.npz
```

정상일 때 행 수, 에피소드 수, 거리 범위, 전진·회전 예시 비율이 나옵니다.
30개 에피소드가 들어 있고 숫자가 `nan`이나 `inf`가 아닌지 봅니다.
직진 예시만 있고 회전 예시가 거의 없으면 모델은 피하는 법을 배우기 어렵습니다.
장애물 배치와 프리뷰를 먼저 확인한 뒤 데이터를 다시 수집하세요.

## 4-4. 실제 환경과의 차이를 기록

교사가 정답처럼 보여도 이 규칙은 최적 주행을 보장하지 않습니다.
막다른 공간에서 제자리 회전하거나, 센서 높이 밖의 물체를 놓칠 수 있습니다.
실물에서도 같은 제한이 드러날 수 있으므로 낮은 상자·투명 물체·바닥 낙하는 피합니다.

실습 노트에 “센서 높이, 공간 크기, 장애물 종류, 바닥 상태”를 기록합니다.
나중에 실제 환경을 비교할 때 쓸 정보입니다.

**완료 확인:** 에피소드가 여러 개이고 전진과 회전 예시가 모두 들어 있습니다.

**기억할 점:** 학습 결과는 교사의 품질과 데이터의 다양성을 넘어서기 어렵습니다.
