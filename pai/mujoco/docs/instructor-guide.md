# 강사 준비 안내

대상은 터미널과 AWS에 익숙하지 않은 참가자도 포함하지만, 로봇 실물 시험에는 숙련된 운영자가 필요합니다. 최소 하루를 잡고 GPU 설치·학습 수렴·하드웨어 리허설 시간은 별도로 확보하세요.

## 행사 전

- 라이선스 문서를 읽고 행사 목적에 맞는 실제 모델 이용 권한을 확보합니다. 불명확하면 자산 없는 개념 수업까지만 운영합니다.
- 행사 AWS 계정의 G 계열 vCPU 한도와 선택 리전의 EC2 용량, SSM 권한을 확인합니다. 워크샵 스튜디오 제공 계정에서 GPU가 자동 제공된다고 가정하지 않습니다.
- 선택 DLAMI, GPU, 소스 커밋, `uv.lock`, 드라이버와 Torch/CUDA 조합을 기록합니다. 64개 환경 스모크를 먼저 수행합니다.
- 4096개 병렬 환경은 공식 안내의 출발점입니다. L4 메모리 용량·학습 시간은 이번 교재 제작 과정에서 측정하지 않았습니다. OOM이면 환경 수를 줄이고 다시 측정합니다.
- 미리 학습한 모델을 제공하려면 배포 권한, 출처, 체크포인트·ONNX 해시와 평가 기록을 준비합니다. 출처 없는 가중치는 교재에 넣지 않습니다.
- 실물은 조립·교정되어 공식 런타임을 실행하는 Microduck을 전제로 합니다. 판매/배송 일정은 제조사에서 확인합니다.
- 지지대, 평평한 바닥, 여유 공간, 충전 상태, 게임패드, 운영자와 로봇을 잡을 보조자를 준비합니다. 학습 모델은 자동 정지 장치가 아닙니다.

## 권장 운영

오전에는 개념·클라우드·설치·스모크까지, 오후에는 학습 결과 읽기·평가·ONNX 검사·실물 절차를 진행합니다. 학습이 수렴하지 않으면 실패 원인을 분석하는 데서 종료해도 학습 목표는 성립합니다. 성공하지 않은 모델을 실물 단계로 넘기지 않습니다.

관찰자에게는 브라우저 교재, 오프라인 관절 개념 뷰어와 공식 온라인 Microduck 시뮬레이터 링크를 제공합니다. Module 5의 3분 미니 실습에서는 한 관절씩 움직이고, Module 6의 그림에서 정책 목표값과 다음 관측의 차이를 말하게 합니다. 공식 데모는 인터넷 연결과 제공자 서비스의 가용성이 필요하며, 행사 목적에 맞는 이용 조건을 먼저 확인합니다. AWS 학습 결과나 실물 로봇과 연결된 화면이 아닙니다. GPU 환경은 2~3인 1개로 시작하되 동시 명령이 섞이지 않게 한 명이 조작합니다. Module 5에서 AWS에 실행하는 Viser의 포트만 SSM으로 전달하며 인터넷에 열지 않습니다. 공식 Hugging Face 데모에는 이 포트 전달이 필요하지 않습니다.

## 중단 기준

NaN, 재현되지 않는 정책, 반복적인 넘어짐, 관절 떨림, 실제 로봇의 모터/온도/배터리 이상, 원격 연결 끊김 시 행동 미확인은 다음 단계로 진행하지 않는 사유입니다. 토크 해제는 로봇이 주저앉을 수 있으므로 지지한 상태에서만 실시합니다. `robotctl health`의 성공만으로 온도·모든 상태가 허용 범위라고 해석하지 않습니다.

## 종료

각 조가 체크포인트와 증거를 private S3에 저장했는지, EC2가 실제 `stopped` 상태인지 확인합니다. S3·EBS·공인 IPv4 등 남아 있는 과금 항목을 확인하고 행사 종료 후 보존·삭제 일정을 정합니다. 모델이나 테스트 로그를 공개 사이트로 자동 업로드하지 않습니다.
