# 오류를 작은 범위부터 확인하기

| 증상 | 먼저 확인 | 다음 행동 |
|---|---|---|
| GPU 배포 거부 | 선택 리전, G/VT vCPU quota, 타입/AZ 제공 | 한도·용량 해결 후 새로 검사. 임의 계정 변경 금지 |
| AMI 검사 거부 | Amazon 소유 GPU DLAMI, Ubuntu, x86_64, root 크기 | 지원 AMI 선택. 검사 우회 금지 |
| 스택 성공 뒤 SSM 연결 실패 | 인스턴스 IAM 역할, SSM Agent, HTTPS egress, 실제 OS 부팅 | CFN 이벤트·SSM 상태 확인. 인스턴스 과금 상태도 확인 |
| `apt-get` 실패 | 아웃바운드 HTTP/HTTPS와 Ubuntu 미러 | 템플릿 변경 이력과 DNS 확인 |
| `uv sync` timeout | 디스크, 인터넷, 다운로드 시간 | 원본 lock을 유지하고 timeout/네트워크 확인 |
| CUDA `False` | 실제 NVIDIA GPU, DLAMI driver, 실행한 venv | 기준 환경에서 점검. CPU 실행을 GPU 성공으로 기록하지 않음 |
| CUDA OOM | 남은 프로세스와 환경 수 | 중복 실행 종료, 4096→1024 등 단계 축소 |
| `list-envs`에 태스크 없음 | 공식 repo 커밋과 `uv sync --frozen` | 설치 오류 해결; 비슷한 태스크 이름으로 대체 금지 |
| 브라우저 흰 화면 | 서버가 출력한 Viser 포트, SSM 터널의 두 포트 | 포트 일치, 탭 새로고침, 서버 로그 확인 |
| 보상은 오르는데 걷지 않음 | 실제 명령이 0인지, 미끄러짐·정지 전략 | 영상과 속도 추종 확인, 실물 배포 보류 |
| ONNX 51차원 | 레거시 정책 또는 다른 태스크 | 현재 61차원 계약과 공식 exporter 확인 |
| ONNX 유한값 검사 실패 | 잘못된 체크포인트·정규화·외부 가중치 | 기준 exporter로 재생성, 의미 검토 |
| 로봇 슬롯 로드 거부 | obs/action 크기, runtime API, 모델 해시 | 설치된 공식 문서와 기준 버전 비교 |
| 실제 로봇이 떨림·넘어짐 | 지지 상태, 관절/센서 교정, 평가 기록 | 시험 중단, 공식 정책 복구, 원인 분석 |

## 도움을 요청할 때 남길 정보

커밋, 정확한 실행 명령, 실행 위치(내 PC/GPU/로봇), OS·Python·GPU/드라이버, 오류의 처음과 마지막 부분, 선택한 정책 해시를 기록합니다. 액세스 키·토큰·개인 네트워크 정보는 공유하지 않습니다.

교재의 `docs/verification.md`에는 제작 시 확인한 검사 범위가 있습니다. 사용자 환경에서 직접 실행한 기록은 별도로 남기세요.

**기억할 점:** 실패한 단계를 성공한 것처럼 건너뛰지 않는 것도 Physical AI를 만드는 핵심 기술입니다.
