왜 Bedrock을 경유하나

도입을 막는 건 모델이 아니라 절차입니다

코딩 에이전트 도입이 늦어지는 이유는 대개 기술이 아닙니다. 새 벤더 계약, 개발자별 좌석 산정, 데이터 처리 검토, 감사 로그 확보 — 이미 한 번 통과한 절차를 벤더마다 다시 반복해야 하기 때문입니다. Bedrock 경유는 이 요청 경로를 이미 승인된 AWS 계정 안으로 옮깁니다. 개발자가 쓰는 도구는 그대로입니다.

01 / 거버넌스

이미 있는 통제를 그대로 씁니다

모델 접근은 IAM 권한으로, 호출 기록은 CloudTrail로, 암호화는 KMS로, 네트워크 격리는 VPC·PrivateLink로. 새 관리 콘솔과 새 권한 모델을 도입하지 않아도 됩니다.

02 / 데이터

추론 리전을 직접 고릅니다

요청은 지정한 리전의 Bedrock 엔드포인트로 나가고, 실제 추론이 실행되는 리전은 고른 경로와 모델 ID가 결정합니다. 데이터 잔류 요건이 있으면 접두사 없는 리전 모델 ID를, 처리량이 우선이면 글로벌 라우트를 고르면 됩니다. 어느 쪽이든 프롬프트와 응답은 모델 학습에 사용되지 않고 모델 제공자와 공유되지도 않습니다.

03 / 개발자 경험

로컬 도구는 그대로입니다

같은 Codex CLI, 같은 IDE 확장, 같은 AGENTS.md· 스킬·MCP·서브에이전트·/review. 바뀌는 것은 요청이 향하는 엔드포인트와, 클라우드 기능 몇 가지가 빠지는 것뿐입니다.

설정 · 공통

설치와 자격증명은 경로와 무관합니다

먼저 이 두 단계를 끝내 두면, 남는 일은 경로 하나를 골라 config.toml에 두 줄 적는 것뿐입니다.

# 환경변수

✓

확인은 /status로. codex를 실행하고 /status를 입력하면 Model provider와 엔드포인트가 보입니다. 어떤 값이 보여야 하는지는 경로마다 다릅니다 — 바로 아래에서 확인하세요. 모델을 바꾸려면 /model, 한 번만 다르게 쓰려면 codex -m <model>을 씁니다.

두 가지 경로

GPT-6 Astra를 쓰는 방법은 두 가지입니다

같은 모델이지만 공급자 값·엔드포인트·모델 ID 형태가 다르고, 추론이 실행되는 리전과 카탈로그도 달라집니다. 하나만 고르면 됩니다.

경로 A OpenAI 문서 기준

Mantle 경로

model_provider = "amazon-bedrock"

Bedrock의 Mantle 엔드포인트로 붙습니다. 모델 ID에 크로스 리전 접두사가 없어, 요청을 보낸 리전에서 추론이 처리됩니다.

# ~/.codex/config.toml
model_provider = "amazon-bedrock"
model = "openai.gpt-6-astra"

/status 엔드포인트
https://bedrock-mantle.us-west-2.api.aws/openai/v1

  • 접두사 없는 리전 모델 ID — openai.gpt-6-astra
  • 카탈로그 6종 — Astra·Sol·Terra·Luna에 GPT-5.5·5.4까지
  • OpenAI 문서가 안내하는 공급자 값
  • AWS GovCloud 리전의 Mantle 엔드포인트는 미지원
이럴 때: 데이터 잔류 요건이 있거나, 문서 표준 구성을 그대로 쓰고 싶을 때
경로 B 크로스 리전 라우트

Bedrock Runtime 경로

model_provider = "amazon-bedrock-runtime"

bedrock-runtime 엔드포인트로 붙습니다. 모델 ID에 global. · us. 접두사를 붙여 라우팅 범위를 고릅니다.

# ~/.codex/config.toml
model_provider = "amazon-bedrock-runtime"
model = "global.openai.gpt-6-astra"

/status 엔드포인트
https://bedrock-runtime.us-west-2.amazonaws.com/openai/v1

  • 라우트 접두사가 추론 리전을 결정 — global.은 전 세계 상업 리전, us.는 미국 지역
  • 카탈로그 4종 × 2라우트 = 8개 항목
  • 여러 리전의 자원을 활용하는 라우팅
  • 지리 경계 요건이 있으면 global.은 부적합
이럴 때: 지리 경계 요건이 없고, 리전 간 라우팅으로 가용성을 넓히고 싶을 때
Mantle 경로와 Bedrock Runtime 경로 비교
항목경로 A · Mantle경로 B · Bedrock Runtime
model_provider amazon-bedrock amazon-bedrock-runtime
엔드포인트 호스트 bedrock-mantle.<region>.api.aws bedrock-runtime.<region>.amazonaws.com
모델 ID 형태 openai.gpt-6-astra — 접두사 없음 global. 또는 us. 접두사 필요
추론 리전 요청을 보낸 리전 접두사에 따라 전 세계 상업 리전 또는 미국 지역
모델 카탈로그 6종 (GPT-5.5·5.4 포함) 4종 × global·us 라우트
공통 AWS 자격증명(SigV4) · OpenAI 호환 Responses API · IAM·CloudTrail·KMS·PrivateLink · 토큰당 과금 · 프롬프트·응답 학습 미사용

호스트 이름은 us-west-2 화면에서 확인한 값을 리전 자리만 일반화한 것입니다. 모델 가용성과 엔드포인트는 리전별로 다를 수 있으니 리전 호환표를 확인하세요.

실제 화면

설정이 붙으면 이렇게 보입니다

두 경로를 각각 붙여 본 실제 터미널 화면입니다. 좌우로 스크롤해 원본 크기로 볼 수 있습니다. 사용자 이름은 가리거나 잘라냈고, 화면에 보이는 세션 ID와 경로는 로컬 값입니다 — 계정 ID나 자격증명은 담겨 있지 않습니다.

아키텍처

요청은 어디로 흐르는가

두 경로 모두 로컬 Codex가 OpenAI 호스팅 API를 거치지 않고, AWS 자격증명으로 서명한 요청을 Bedrock의 OpenAI 호환 엔드포인트에 직접 보냅니다. 다른 것은 엔드포인트와 모델 ID입니다.

경로 A

Mantle 경로

amazon-bedrock → bedrock-mantle.us-west-2.api.aws/openai/v1

모바일에서는 다이어그램을 세로로 회전해 보여 줍니다.

경로 B

Bedrock Runtime 경로

amazon-bedrock-runtime → bedrock-runtime.us-west-2.amazonaws.com/openai/v1

모바일에서는 다이어그램을 세로로 회전해 보여 줍니다.

1 · AWS 자격증명 (SSO · 프로파일 · Bedrock API 키) 2 · SigV4 서명된 HTTPS 추론 요청 3 · 모델 호출 (경로 B는 global·us 크로스 리전 추론)
모델

Astra 하나만 쓰지 않아도 됩니다

모델 ID의 앞부분은 경로에 따라 달라집니다 — Mantle은 openai., Runtime은 global.openai. 또는 us.openai.. 기본값은 어느 쪽이든 Sol입니다.

경로 B에서는 접두사가 추론 리전을 정합니다. global.*은 전 세계 상업 리전으로 요청을 보내는 글로벌 크로스 리전 추론 프로파일이고, us.*는 미국 지역 안으로 범위를 좁힌 지역 프로파일입니다. 지리 경계 요건이 있는 워크로드라면 global.*은 피하고, 경로 A의 접두사 없는 리전 모델 ID를 쓰세요. GPT-6 Astra는 최대 100만 입력 토큰 컨텍스트를 지원하며(화면 표시 1.05M), 모델 가용성은 리전마다 다르므로 선택 전 리전 호환표를 확인하세요.

운영과 보안

기존 AWS 통제 위에서 돌아갑니다

IAM 권한

어떤 팀이 어떤 모델을 호출할 수 있는지 IAM 정책으로 정합니다. 모델 접근 권한이 없으면 호출은 실패합니다.

CloudTrail 감사

모델 호출 활동을 기존 감사 파이프라인에서 그대로 추적합니다. 별도 감사 API가 필요 없습니다.

KMS · PrivateLink

암호화와 네트워크 격리에 이미 쓰고 있는 KMS 키와 VPC·PrivateLink 구성을 그대로 적용합니다.

과금과 계약

토큰당 과금이며 개발자별 좌석 라이선스나 별도 약정이 없습니다. 사용량은 기존 AWS 약정에 반영됩니다.

미리 알아 두면 좋은 것들

  • 인증은 두 갈래입니다. Bedrock API 키(AWS_BEARER_TOKEN_BEDROCK)를 먼저 확인하고, 없으면 AWS SDK 자격증명 체인(aws sso login, AWS_PROFILE, 액세스 키, credential_process 페더레이션)을 따릅니다. API 키를 쓸 때는 리전을 반드시 지정하세요.
  • 데스크톱 앱과 IDE 확장은 셸 환경변수를 물려받지 않습니다. ~/.codex/.env에 값을 넣고 앱·확장을 재시작하세요.
  • 경로를 섞어 쓰면 안 됩니다. amazon-bedrock에 접두사가 붙은 모델 ID를 적거나 그 반대로 적으면 모델 ID가 카탈로그와 맞지 않습니다. 공급자 값과 모델 ID는 같은 경로의 짝으로 맞춰 주세요.
  • 데이터 잔류 요건이 있으면 라우트를 통제하세요. 글로벌 프로파일(global.*)은 지리 경계 요건이 없는 워크로드용입니다. 어떤 모델과 프로파일을 호출할 수 있는지는 IAM 정책으로 제한할 수 있습니다.
  • 지원 창구가 나뉩니다. 클라이언트 설정·CLI 동작은 OpenAI 지원, AWS 자격증명·IAM 권한·모델 접근· 쿼터·과금·리전 가용성·Bedrock 요청 실패는 AWS 지원 또는 계정 관리자에게 문의합니다.
  • GovCloud는 대상이 아닙니다. 로컬 Codex 표면은 AWS GovCloud 리전의 Bedrock Mantle 엔드포인트를 지원하지 않습니다.

붙이는 데 필요한 건 네 줄입니다

공통 부분을 붙여 넣고, config.toml에서 두 경로 중 하나만 남기세요.

npm install -g @openai/codex
export AWS_PROFILE="<your-aws-profile>"
export AWS_REGION=us-west-2

# ~/.codex/config.toml — 경로 A · Mantle
model_provider = "amazon-bedrock"
model = "openai.gpt-6-astra"

# ~/.codex/config.toml — 경로 B · Bedrock Runtime
model_provider = "amazon-bedrock-runtime"
model = "global.openai.gpt-6-astra"

codex        # 실행 후 /status 로 공급자 확인
Codex 내려받기 Bedrock 설정 문서 리전 호환표
