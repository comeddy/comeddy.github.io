# 파일을 확인한 뒤 한 단계씩 움직이기

예상 시간: 운영자 판단에 따름. 모델 적용은 실제 동작을 바꿉니다. 이전 단계의 시뮬레이션 검토와 실물 준비를 완료한 경우에만 진행합니다.

## 1. 내 컴퓨터로 전달 묶음 받기

모듈 8에서 생성한 묶음 디렉터리를 사용합니다. 공개 웹사이트에 올리는 대신 private S3와 로컬 네트워크를 사용하세요.

```bash
aws s3 cp "s3://$ARTIFACT_BUCKET/runs/my-walk/bundle/"   ./artifacts/downloaded-bundle/ --recursive --region "$AWS_REGION"
```

받은 묶음의 검사 방법은 [정책 검사 도구](../../docs/policy-tools.md)의 `verify` 절차를 따릅니다. 다른 컴퓨터로 옮길 때마다 해시를 다시 확인합니다. `physical_trial_authorized: false`는 자동 검사가 실제 시험을 승인하지 않는다는 뜻입니다. 이 필드를 `true`로 바꾸어 문제를 해결하려 하지 마세요.

## 2. 로봇으로 파일만 복사

아래 로봇 계정·주소를 실제 값으로 바꿉니다. 실행 중인 정책 파일을 직접 덮어쓰지 않습니다.

```bash
scp -r artifacts/downloaded-bundle 로봇사용자@로봇주소:~/workshop-bundle
ssh 로봇사용자@로봇주소
cd ~/workshop-bundle
sha256sum -c checksums.sha256
robotctl health
robotctl policy list
```

묶음 파일 이름이 도구 문서와 일치하는지 확인하세요. 실패한 해시를 무시하거나 체크섬 파일을 다시 만들어 통과시키지 않습니다. 송신 측에서 기록한 해시와도 대조해야 합니다. 해시는 전송 무결성을 확인하며 작성자 서명을 대신하지 않습니다.

## 3. 지지된 상태에서 walk 슬롯 적용

정책 실행을 중지하고 로봇을 지지합니다. 로봇이 이미 걷는 중이라면 `policy load`가 초기 자세로 이동한 뒤 다시 구동할 수 있으므로 먼저 상태를 정리해야 합니다.

```bash
sudo robotctl policy load walk "$HOME/workshop-bundle/policy.onnx"
robotctl policy list
robotctl health
```

이 명령은 공식 슬롯 로더를 사용합니다. 관측/행동 크기와 런타임 API 등이 맞지 않으면 중단해야 합니다. 동작 중인 데몬에 직접 UART 명령을 보내거나 다른 모터 프로그램을 동시에 실행하지 마세요.

## 4. 첫 동작 순서

1. 지지대에서 기본 자세와 급격한 관절 움직임·진동 여부를 확인합니다.
2. 운영자가 허용하면 바닥에서 이동 명령 0으로 짧게 균형을 확인합니다.
3. 훈련·평가한 범위 안의 낮은 전진 명령으로 짧게 움직이고 스틱을 놓아 정지를 확인합니다.
4. 반복적인 넘어짐, 과열, 떨림, 비정상 소리, 끊김 대응 미확인이 있으면 종료합니다. 그 자리에서 제한값을 임의로 올리지 않습니다.
5. 실제 정책 해시·펌웨어·배터리·바닥·관찰 시간·결과와 운영자를 기록합니다.

교재에 모든 로봇에 보편적으로 안전한 속도 숫자를 지정하지 않았습니다. 시뮬레이션에서 0.1 m/s를 시험한 것이 그 속도의 실물 안전성을 보장하지 않습니다.

## 5. 공식 정책으로 복구

로봇을 지지하고 정책 실행을 중지한 상태에서:

```bash
sudo robotctl policy reset walk
robotctl policy list
robotctl health
```

현재 설치된 공식 세트의 walk 슬롯으로 복원됩니다. 이전에 다른 사용자 정책을 쓰고 있었다면 그 정책 경로와 설정을 미리 기록해 두어야 합니다. 이 reset이 모든 임의 사용자 설정을 되돌리는 것은 아닙니다.

**확인:** 실제로 수행한 시험만 기록합니다. 파일 복사, 정책 로드, 보행 확인은 각각 따로 기록하세요.

**기억할 점:** 배포의 완료 조건은 파일 업로드가 아니라 관찰한 실제 동작과 복구 가능성입니다.
